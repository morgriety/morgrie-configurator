# MORGRIE Configurator 测试与验收规则

本文件是测试与验收流程的补充规范，不覆盖现有开发、代码修改、Git、设备通信与固件安全、UI 设计及部署规则。若发现与现有规则冲突，停止相关修改并报告，不擅自决定优先级。

## 1. 测试任务组织

- 每次测试一次性提供完整验收清单。
- 不再每完成一项就要求用户返回汇报。
- 用户完成一轮测试后统一反馈结果。
- 不重复询问已经确认的信息。
- 每款键盘分别保留独立的验收结果。

## 2. 统一验收清单格式

每项必须包含：

- 编号
- 功能名称
- 验收内容
- 测试结果

结果统一使用：

| 状态 | 含义 |
| --- | --- |
| OK | 测试正常 |
| NG | 测试异常 |
| N/A | 设备不支持或项目不适用 |
| 待测 | 尚未执行测试 |

测试清单提供独立备注区域，方便用户集中说明异常。

## 3. 交互式反馈

在 ChatGPT 支持交互控件时：

- 提供可直接选择 OK / NG / N/A / 待测的验收表。
- 提供备注输入区域。
- 提供「复制验收结果」功能。
- 复制内容应包含设备型号、各项编号、结果及备注。

在不支持交互控件的环境中，提供可直接复制填写的 Markdown 或纯文本清单。

不得为了实现交互式验收而修改 Configurator 产品代码或新增网页功能。

## 4. 测试结果管理

- 软件模拟测试与真实设备测试必须分开记录。
- 未执行的测试不得标记通过。
- 用户明确反馈 OK 的项目记录为实机通过。
- 用户反馈 NG 的项目保留异常说明。
- 已通过的项目原则上不重复测试，除非存在明确的回归测试需求。
- 已决定暂缓的问题保留记录，不反复要求用户测试。
- 新发现的问题统一登记在 `docs/ISSUES.md`。
- 已存在的问题保持原编号，不随意删除、重新编号或覆盖历史证据。

本文件的 OK / NG / N/A / 待测是验收结果状态，不替换 `docs/ISSUES.md` 的问题处理状态。现有问题编号、状态和历史证据保持原样。历史验收步骤不构成当前设备写入或重新启动暂缓测试的授权。

## 5. 设备操作安全

- 涉及改键、宏、灯光、布局及备份导入等写入操作，必须先确认用户授权。
- 测试前尽可能备份原始配置。
- 测试完成后恢复原配置。
- 不擅自执行固件刷写、恢复出厂或清除设备配置。
- 不将软件测试通过等同于实机验收通过。
